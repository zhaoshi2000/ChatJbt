逗包 / Java Stream Chat 一键停止脚本
==================================

一、放在哪里

把 stop-all.bat 和 stop-all.ps1 两个文件一起复制到当前项目根目录，
与 run-doubao-web.bat 或 run-app.bat 放在同一层。例如：

Doubao\
  run-doubao-web.bat
  stop-all.bat        ← 双击这个
  stop-all.ps1        ← 必须与 BAT 一起保留
  config\
  data\
  out\

这是独立脚本包，不需要替换后端 JAR，也不会改动已有扩展或配对令牌。
不能在 ZIP 预览窗口里直接运行，必须先解压。

二、怎么运行

先保存未发送的草稿，然后双击 stop-all.bat。
出现“权限不足”或无法读取进程时，右键 stop-all.bat → 以管理员身份运行。
窗口会显示识别出的 PID、停止结果和端口是否释放，执行后保留窗口供查看。

三、停止范围

1. 检查默认端口 48643（逗包）和 48627（旧 Java Stream Chat）。
2. 同时读取当前项目 config/application.properties 的 server.port、PORT 环境变量。
3. 扫描已经交付的后端/客户端 JAR 的运行进程；能够根据原始 class 指纹识别的后端，
   即便使用其他端口，也会进一步检查其监听端口。
4. 可识别原来的 Swing 桌面客户端，以及已交付客户端 JAR 的 JavaStreamChat.exe 包装版。
5. 只在能够确认项目身份时结束进程；绝不只因占用了指定端口或名字叫 java.exe 就结束。

普通使用无需自己填写配对令牌。脚本会尝试从当前项目和已确认的运行目录读取
本地 data/local-token.txt，以及配置指定的数据目录；令牌不会显示出来或写入日志。
所有 HTTP 请求仅发送到 127.0.0.1，并禁用系统代理与重定向。

四、停止顺序

有可用令牌时：读取本地任务列表 → 取消未结束任务 → 留出网页桥接同步时间 →
调用 /admin/shutdown → 等待后端退出 → 关闭桌面客户端 → 检查剩余进程与端口。

找不到令牌、令牌不匹配、接口无响应或正常退出失败时：
只对已确认身份的项目进程使用后备终止，并再次核对进程创建时间/启动参数。
如果权限不足或身份不明，脚本会跳过并显示 PID，不会扩大结束范围。

强制结束可能丢失未落盘内容；未成功同步取消的任务也可能在后端下次启动时恢复。
运行期间不要在其他页面继续提交新任务；重新启动的实例不属于本轮初始进程快照。

五、不会做的事情

不会停止 Windows 系统服务，不会批量结束所有 Java，不会关闭 Edge/Chrome，
不会删除聊天记录、data 目录、令牌、日志，也不会卸载/改写浏览器扩展。
原来的 cmd /k 命令行窗口可能保留，但 Java 后端已经停止；是否成功以 PID/端口结果为准。

网页和后端由同一个 Java 进程提供，因此不需要再额外结束 Node/Nginx 等服务。
浏览器扩展仍可能在浏览器内运行并重试本机连接。
彻底停用网页桥接：在扩展管理页禁用“逗包 · 后台桥接”及旧 Java Stream Chat。
已经提交到 ChatGPT 网页的生成只能尽力取消；必要时在工作标签页手动点击停止。
不要为了停止桥接而强行结束整个浏览器，以免影响其他标签页。

六、可选命令（在本文件所在目录的 PowerShell 中执行）

只检查，不取消任务、不停止项目：
  .\stop-all.bat -PreviewOnly

只尝试正常退出，不强制结束：
  .\stop-all.bat -NoForce

再检查指定端口，仍然先验证项目身份：
  .\stop-all.bat -ExtraPorts "51234,51235"

返回码：
  0：已识别的目标已停止且检查端口已释放；预览模式则表示检测完成。
  1：脚本运行失败或环境不支持。
  2：有未确认/未处理进程，或端口仍被占用。不能据此说所有服务均已停止。

七、兼容性与测试边界

面向 Windows 10/11 自带 Windows PowerShell 5.1 编写，包含 UTF-8 BOM 和 CRLF。
旧版相对路径 JAR 会尝试调用同一 Java 安装目录中的 jcmd，最多等待 2.5 秒。
没有 jcmd 时，后端可通过已知协议识别，旧客户端可通过已知标题辅助识别；
仍无法确认的进程会被跳过。重新编译/修改过的 JAR 指纹可能不同，不会仅凭文件名终止。

已在 Linux + Java 21 下，对对话中实际交付的三个版本后端验证身份检查、令牌鉴权、
任务取消、正常关闭、进程退出、端口释放与文件保留；同时核对了脚本中的 class 指纹。
32 项检查通过。检查由 Python 驱动 HTTP 请求，并不是在 Windows 上运行了此脚本。
脚本另经过静态引号/括号检查，但此环境没有 PowerShell，不等于完成 PowerShell 语法解析。
Windows BAT、PowerShell 执行、WMI 进程识别/终止、浏览器取消尚未真机验收。
测试范围及结果见 TEST-REPORT.json。
